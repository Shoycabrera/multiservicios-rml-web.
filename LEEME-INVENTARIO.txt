MULTISERVICIOS RML — INVENTARIO Y FOTOS
======================================

1) INVENTARIO
--------------
Edita únicamente inventario-unidades.js para datos y estado de cada unidad.

Estados:
  disponible
  reservado
  proximamente
  oculto
  no-disponible (opcional)

"oculto" = la unidad existe pero no se publica.
Las fotos NO controlan la visibilidad.

Actualmente están precargados los IDs canónicos:
  R001 a R100
  LM01 a LM70

Los campos modelo, año, km, transmisión, color y uso pueden quedar vacíos.

2) FOTOS
---------
No hace falta crear carpetas vacías para todas las unidades.
Cuando una unidad tenga fotos, el optimizador genera una carpeta lista para arrastrar a:

  assets/img/unidades/

Ejemplo de salida:

  R090/
    01.webp      <- foto principal
    02.webp
    03.webp
    fotos.json   <- índice para una galería futura

La tarjeta intenta cargar siempre:
  assets/img/unidades/<UNIDAD>/01.webp

Si no existe, usa automáticamente la imagen de muestra del modelo.

3) FOTOS ADICIONALES
---------------------
La web no necesita un manifiesto global. Cada carpeta es autónoma.
`fotos.json` pertenece a la propia unidad y se usará para el carrusel futuro.

4) OPTIMIZADOR
---------------
El optimizador debe ser secuencial y portable:
  - seleccionar una carpeta de entrada
  - indicar el ID de unidad
  - exigir una imagen principal llamada exactamente 1.*
  - aceptar nombres libres para las demás imágenes
  - convertir todo a WebP
  - generar 01.webp, 02.webp, 03.webp...
  - generar fotos.json
  - devolver una carpeta <UNIDAD>/ lista para arrastrar al repositorio

Consulta docs/ESTANDAR-IMAGENES.md y docs/PROMPT-OPTIMIZADOR-IMAGENES.md.
